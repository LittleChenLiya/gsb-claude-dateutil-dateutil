Added :func:`dateutil.parser.parse_strict`, :class:`dateutil.parser.StrictParser` and :class:`dateutil.parser.StrictParseResult`, a strict candidate-based entry point for inputs whose day/month order is ambiguous. Instead of guessing a single order, the parser tries every declared candidate, keeps only results satisfying the caller's date range and default field policy, merges candidates that resolve to the same actual datetime, and reports whether the outcome is unique, ambiguous or has no solution. The parser never consults the current date; missing fields are taken from the injected ``default`` base date. The default :func:`~dateutil.parser.parse` behaviour is unchanged.
